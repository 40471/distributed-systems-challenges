# Challenge 2: Unique ID Generation

## Goal

Implement a globally unique ID generator that remains totally available, even during network partitions.

The node receives a `generate` request and must return a `generate_ok` response containing an ID that does not collide with IDs generated by any other node.

## What I Learned

- Total availability means a node must keep responding even when it cannot communicate with other nodes.
- Coordination is expensive and sometimes impossible under partitions.
- A distributed system can often preserve correctness by designing local operations that are globally safe.
- Unique ID generation is a good example of avoiding coordination entirely.

## Approach

The solution combines the Maelstrom node ID with a node-local atomic counter:

```text
<node-id>-<counter>
```

This satisfies the main distributed-systems requirement: the system remains available because ID generation is local. A node does not need to contact any other node before replying.

The counter is an `atomic.Uint64`, so concurrent `generate` requests on the same node cannot observe the same counter value.

## Tradeoffs

This design makes the uniqueness argument explicit:

- The node ID separates each node's ID namespace.
- The local counter prevents duplicates within a single node.
- No network communication is required.

The main tradeoff is that these IDs are tied to the Maelstrom node identity and are not random. That is acceptable for the challenge and useful for learning, but a production system might choose UUIDs, ULIDs, Snowflake-style IDs, or another scheme depending on ordering, size, persistence, and operational requirements.

## How To Run

From this directory:

```sh
make build
```

To run Go tests:

```sh
make test
```

To run the Maelstrom workload, provide the path to your local Maelstrom binary:

```sh
make test-maelstrom MAELSTROM=/path/to/maelstrom
```

## Future Improvements

- Persist the counter if node restarts need to be supported.
- Consider Snowflake-style IDs if sortable numeric IDs are required.
